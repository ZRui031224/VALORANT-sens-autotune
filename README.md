# 无畏契约灵敏度生成器 · VAL SENS LAB

一个**单文件、纯前端、离线可用**的《无畏契约》（VALORANT）个人灵敏度生成器。

打开网页 → 填写你的 DPI 与操作习惯 → 跑一遍内嵌的瞄准测试 → 得到能**直接填进游戏**的三位小数灵敏度，以及它的推荐区间、可信度和完整推导过程。

**在线版**：<https://zrui031224.github.io/VALORANT-sens-autotune/> —— GitHub Pages 托管，打开即用，无需下载。

> 本文档描述的是 `index.html` 的**实际行为**：所有数值、公式、测试规则、字段名称都与代码一致。

## 1. 项目解决什么问题

**「我该用多少灵敏度？」**——这个问题看似简单，实际有三个坑：

1. **抄职业选手没用。** 同一个 `0.35`，在 800 DPI 和 1600 DPI 下差一倍；同样是 0.35，手臂流和手腕流、45 cm 和 90 cm 鼠标垫，手感也完全不同。真正可比的是 **cm/360°**（转一整圈鼠标要走多少厘米），而这需要换算。
2. **目标感模糊，调参靠玄学。** 凭感觉"再快一点"，往往在 0.33 ↔ 0.38 之间反复横跳，既没有数据，也分不清是灵敏度不合适还是当天状态差。
3. **换算器和测试是割裂的。** 大部分网页只给 cm/360° 换算；训练软件（Aimlabs 等）又需要单独安装、单独设置 FOV，测出来的结果还得自己反推。

**本项目的做法**：把「换算」和「测量」放进同一个网页。测试画面按 VALORANT 原生参数绘制（yaw `0.07°/计数`、横向 FOV `103°`），所以你在测试里的肌肉记忆与游戏内**同源**；再在同一套几何下对比 3~4 个灵敏度档位的表现，用统计方法估出最优点，并给出一个**推荐区间**而不是假装精确的单点。

一句话：**用你自己的手、你自己的桌面、你自己的 DPI，测出你自己的数值。**

## 2. 项目主要功能

### 2.1 习惯档案 → 测试起点

在正式测试前，先读取以下参数，推导出一个"测试起点"（不是最终答案）：

| 输入项 | 取值 | 作用 |
|---|---|---|
| 鼠标 DPI | 100–32000 | 换算的核心参数，必须与鼠标驱动一致 |
| 当前游戏灵敏度 | 0.1–10.0，可留空 | 留空则按习惯推导；填写则直接作为测试起点，三档围绕它取 0.80×–1.25× |
| 鼠标垫可用宽度 | 10–200 cm | 约束 180° 回正不超过垫面 |
| 显示器刷新率 | 60 / 144 / 165 / 180 / 240 / 360 / 500 | 记录用，不参与计算 |
| 主要发力方式 | 大臂流 / 手臂+手腕 / 手腕流 | 影响起点快慢（×1.07 / ×1.00 / ×0.92） |
| 常用定位 | 决斗·高频对枪 / 全能·混合位 / 控场·哨位 / 狙击·精准优先 | 基准 cm/360°（33 / 38.5 / 43 / 49） |
| 常见失误 | 经常甩过头 / 比较均衡 / 经常甩不到 | 起点修正（×1.06 / ×1.00 / ×0.94） |
| 手感偏好 | 0–100 滑杆 | 起点修正（×0.91 ~ ×1.09） |

起点值会实时显示在首屏卡片里（灵敏度、eDPI、cm/360°、180° 行程）。

### 2.2 内嵌 5 个测试

全部在同一个 Canvas 舞台里完成，**不需要点击目标**：

| 编号 | 测试 | 目标数 / 时长 | 目标角半径 | 出现距离 | 单目标限时 |
|---|---|---|---|---|---|
| A | **悬停甩枪**（类 Aimlabs Gridshot） | 12 个 | 3.2° | 9°–29° | 5 s |
| B | **微目标精准** | 16 个 | 1.7° | 3°–10° | 1.8 s |
| C | **动态追踪** | 12 s | 2.6° | 视野内连续移动，峰值约 30°/s | — |
| D | **180° 转身校准** | 4 个 | 3.4° | 128°–175°（侧面/身后） | 6 s |
| E | **试枪房**（自由练习） | 无限 | 3.2° | 8°–26° | 无 |

- A 用于大角度定位速度，B 是拟合曲线的**核心依据**，C/D 用于复核（极端情况下才会触发微调）。
- D 的目标在身后时会显示屏幕边缘的方向箭头。
- E 中按 `-` / `=` 以 1% 步长实时微调（0.85×–1.15×），按 `Esc` 结束并返回结果。

### 2.3 三个容易做错的交互细节

| 需求 | 实现方式 |
|---|---|
| **碰到就触发，不用点击** | 命中判定用**角距离**：准星与目标中心的夹角 ≤ 目标半径即命中；并且做**线段扫掠检测**，快速甩枪时一帧跨过目标也不会漏判 |
| **鼠标要有准星** | 指针锁定后隐藏系统光标，在画布正中绘制薄荷绿准星（带深色描边，暗背景下不丢） |
| **倒计时不能卡** | 不累加 `setInterval`，全部用 `performance.now()` 墙钟计算相位；另有 100 ms 看门狗定时器兜底，即使 rAF 被节流，倒计时数字也照走 |

### 2.4 一键智能生成（自适应测量）

点「开始智能测试」后会自动跑完以下 7 个环节：

```
热身 8 目标（不计分）
  ↓
第 1~3 轮：0.80× / 1.00× / 1.25× 三档，每档 16 个目标，顺序随机（抵消热手与疲劳）
  ↓
汇总拟合 + 决定精修点
  ↓
精修轮：在峰值附近再补 16 个目标
  ↓
甩枪复核（12 目标）+ 动态追踪复核（12 s）
  ↓
输出结果
```

单次约 **2 分半**。关键设计：

- **轮次累计**：每次测试的轮次会并入同一条曲线，同一灵敏度上的多轮直接取平均，**不清空历史**。
- **固定几何**：所有档位共用同一串目标方向（16 个固定角度），把"这一轮运气好/坏"的影响压到最低。
- **收缩估计**：最终值 = 拟合顶点 45% + 实测最高分点 55%（对数域），并硬性限制在最高分点 ±25% 内，避免顶点乱跳。

### 2.5 结果输出

| 输出 | 说明 |
|---|---|
| **游戏灵敏度** | 三位小数、范围 0.1–10.0，可直接键入游戏 |
| 推荐区间 | 得分不低于峰值 90% 的区间（并夹在 ±7% 内），区间内差别属测量噪声 |
| eDPI / cm/360° | 当前 DPI 下的换算值 |
| 180° / 90° 手臂行程 | 转身与微调各需要扫多少厘米 |
| 三档取值 | 稳定型（×0.94）/ 平衡型（×1.00）/ 速度型（×1.06），可分别复制 |
| 测试可信度 | 10%–96% 的启发式指标（见 [技术原理](#6-技术原理)） |
| 历次一致性 | 最近几次自动测试结果的波动百分比 |
| 换 DPI 换算 | 只改 DPI 时对应的新灵敏度 |
| 开镜倍率迁移 | 新倍率 = 旧灵敏度 × 旧倍率 ÷ 新灵敏度 |
| 完整报告 | 一键复制纯文本报告（含推导日志） |

### 2.6 本地持久化

档案、每轮成绩、历次结果都保存在浏览器 `localStorage`（键名 `val_sens_lab_v3`），刷新或次日再打开仍然在。结果页底部有「清空所有数据」。

## 3. 安装方法

**本项目没有构建步骤、没有依赖、不联网。** 一个 HTML 文件就是全部。

### 环境要求

| 项 | 要求 |
|---|---|
| 浏览器 | Chrome / Edge 桌面版（需支持 Pointer Lock；`unadjustedMovement` 用于绕过系统指针加速，不支持时会自动退回普通锁定） |
| 系统 | Windows 10/11（推荐）、macOS、Linux 桌面版 |
| 显示器 | 建议 16:9；测试区强制 16:9 并锁定 103° 横向 FOV |
| 外设 | 鼠标（必须）；手机 / 触屏无法使用 |
| 网络 | 不需要 |

### 方式一：直接打开（推荐）

1. 下载 `index.html` 到本地任意目录（或直接把仓库克隆下来）。
2. 双击，或拖进 Chrome / Edge 窗口。
3. 看到首屏"当前测试基准"有具体数值（如 `0.420`）即加载成功。

### 方式二：本地静态服务器（可选）

某些环境下（例如文件被放入受限目录、或需要通过 `http://` 访问）可以用任意静态服务器：

```bash
# 在文件所在目录执行，任选其一
python -m http.server 8080
# 或
npx serve .
```

然后浏览器访问 `http://127.0.0.1:8080/index.html`。

### 校验是否正常

- 首屏"当前测试基准"显示如 `0.420 / 336 eDPI / 38.9 cm`（随你填的参数变化）。
- 点任意测试卡 → 出现说明面板 → 点「开始测试」→ 浏览器请求锁定鼠标 → 出现准星和 3-2-1 倒计时。
- 若提示"鼠标锁定失败"，见 [第 4.5 节](#45-常见问题排查)。

## 4. 使用方法

### 4.1 测试前准备（重要）

1. **关闭 Windows 指针加速**：设置 → 蓝牙和其他设备 → 鼠标 → 其他鼠标设置 → 指针选项 → 取消勾选「提高指针精确度」。
2. **浏览器缩放 100%**：`Ctrl` + `0`。
3. **确认 DPI**：以鼠标驱动 / 板载配置里的值为准，测试中途不要切换 DPI 档位。
4. **一次测完**：中途不要改分辨率、不要换鼠标垫位置。

### 4.2 五步走

1. **填档案**（第 01 区）：至少填对 DPI；知道当前灵敏度就填上。
2. **点「开始智能测试」**（第 02 区）：先热身，再依次跑 3 个档位、精修、甩枪、追踪。
3. **看结果**（第 04 区）：记下大号数字，以及它下面的"推荐区间"。
4. **填进游戏**：设置 → 常规 → 鼠标 → 灵敏度：瞄准，输入三位小数。
5. **（可选）试枪房验证**：用结果灵敏度进第 03 区的试枪房练 1 分钟，手感不对就用 `-` / `=` 微调后再决定。

### 4.3 测试中的操作

| 操作 | 效果 |
|---|---|
| 移动鼠标 | 转动视角；准星固定在屏幕正中 |
| 让准星碰到红圈 | 自动命中，**不需要点击** |
| `Esc` | 解除鼠标锁定并暂停（暂停会作废当前轮，继续时重新开始本轮） |
| `-` / `=`（仅试枪房） | 以 1% 步长降低 / 提高当前测试灵敏度 |
| 「结束本次测试」 | 放弃当前轮 |

### 4.4 怎么读结果

- **推荐区间才是重点**：例如 `0.405 – 0.467`，说明这个范围内你的表现差异在测量误差以内，取中间值即可，不必纠结第四位小数。
- **可信度**：由档位数、累计轮次、拟合优度、复核项、历次一致性共同决定，是启发式指标，不是概率。
- **历次一致性**：≤6% 显示绿色（稳定）；6%–12% 橙色（正常噪声）；>12% 红色（建议再测一轮）。
- **建议**：连测 2–3 次，取最后一次的结果与区间；每次约 2 分半，轮次会自动累计。

### 4.5 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 点「开始测试」没反应 / 提示锁定失败 | 页面在 iframe 里（需 `allow="pointer-lock"`）；或浏览器拦截了指针锁定。用顶层标签页打开，再点一次 |
| 鼠标动了视角不动 | 没拿到指针锁定；看是否按过 `Esc`，点「继续测试」重新锁定 |
| 测试里目标"飘" | 浏览器缩放不是 100%，或 Windows 指针加速没关 |
| 结果和上次差很多 | 前几次测试样本少属正常；新版会累计轮次，连测 2–3 次后波动通常降到 6% 以内 |
| 换了 DPI 后结果区变空 | 正常：统计只取**当前 DPI** 的轮次，改回原 DPI 或重新测一次即可 |

## 6. 技术原理

### 6.1 换算

VALORANT 的 yaw（每个鼠标计数的转角）为 **0.07°**，灵敏度直接线性缩放：

```
每计数转角      = 0.07° × 灵敏度
cm/360°        = 2.54 × 360 ÷ (灵敏度 × DPI × 0.07)
               = 13062.86 ÷ (灵敏度 × DPI)
灵敏度          = 13062.86 ÷ (cm/360° × DPI)
eDPI           = 灵敏度 × DPI
```

测试画面同样按这个比例旋转视角，因此测试里的一次甩枪与游戏里的一次甩枪**物理位移相同**。

### 6.2 计分

每轮微目标测试的得分：

```
score = 命中率 × (1000 ÷ 中位命中用时ms) × (0.85 + 0.15 × 路径效率)
```

用**中位用时**而不是总用时：单个目标超时只会通过命中率扣分，不会连带把整轮的时间指标一起拖垮，轮次间方差因此小得多。

### 6.3 估计

1. 同一灵敏度的多轮 → 得分取平均；
2. 对 `(ln 灵敏度, 得分)` 做最小二乘二次拟合 `y = ax² + bx + c`；
3. 顶点 `x* = -b/(2a)`（限制在实测范围内 ±8%）；
4. 收缩：`exp(0.45·ln(x*) + 0.55·ln(最高分点))`，并夹在最高分点 ±25% 内；
5. 推荐区间：`y ≥ 0.90 × 峰值` 的解集，夹在 ±7% 内；
6. 复核规则只在极端情况触发：甩枪命中率 <75% → ×0.96；追踪覆盖率 <35% → ×0.97；转身完成 <2 次 → ×1.05；
7. 鼠标垫约束：`cm/360° ≤ 垫宽 × 1.45`；
8. 最终夹到 0.1–10.0 并保留三位小数。

### 6.4 可信度

启发式加权（0.10–0.96）：有效档位数、累计轮次、拟合 R²、甩枪/追踪/转身是否完成、历次波动是否 ≤6%。**它表示"这组数据有多扎实"，不是统计置信度。**

## 9. 已知限制

1. **必须桌面端 + 鼠标**：依赖 Pointer Lock 与原生鼠标计数，手机/触屏无法使用。
2. **需要顶层窗口**：嵌入式 iframe 必须带 `allow="pointer-lock"`；否则无法锁定鼠标。
3. **画幅假设 16:9**：测试区强制 16:9 并锁定 103° 横向 FOV；带鱼屏或 4:3 拉伸会有少量差异。
4. **测量本身有噪声**：这类测试的物理下限约 ±5–7%；推荐区间表达的就是这个不确定性，不要把它当成"精确到 0.001"。
5. **不是 Aimlabs 的替代品**：测试为独立实现（类 Aimlabs 的悬停甩枪），用于灵敏度标定，不含完整训练课程与排行榜。
6. **非官方工具**：与 Riot Games 无关联，VALORANT / 无畏契约 相关名称归其权利人所有。
